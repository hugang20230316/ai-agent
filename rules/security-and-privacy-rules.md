# Agent 安全、隐私与同步边界规则

## 敏感信息

- 不把密码、token、cookie、连接串、浏览器会话、私有截图或本机绝对路径写进公开规则、模板、代码、文档、提交记录或最终答复。
- 用户明确要求排查、联调、复现或验证接口时，测试地址、内网地址和内部主机可以在当前私有聊天或本机私有文件中给出可用值；禁止写入公开规则、模板、代码、对外文档或提交记录。对外输出时仍按最小必要原则脱敏。
- 用户明确要求账号、手机号、ID 等作为查数据、复现、登录测试或接口入参时，不要默认打码到不可用；优先用聊天里的控制台短表或本机私有文件给出可直接复制的值。若这些值是生产真实个人信息或对外输出内容，再按最小必要原则脱敏。
- SQL、DSL、Redis key、队列名、日志片段或业务标识含密码、token、cookie、session、API key、私钥、连接串等凭据值时，先脱敏再展示。
- 发现 token、密码或 cookie 已进入聊天、日志、审批规则或提交记录时，先删除本地残留，再提示用户在平台撤销该凭据。

## 私有配置

- `config.toml`、`.codex/local/`、会话、日志、sqlite、缓存、浏览器状态、凭据和内部环境配置都是本机私有内容，不同步、不上传。
- `rules/default.rules` 是本机命令审批历史，不是沟通或开发规则，不上传、不引用。
- 需要区分公共规则和平台差异时，公共规则只写通用行为；路径、脚本、端口、账号和平台细节只写入本机私有配置、环境变量或运行时自动检测。
- 公共规则只描述行为，不写机器路径、浏览器 profile、会话文件、平台命令或本机脚本绝对路径。

## 文件系统破坏防护

- 执行递归删除、覆盖式清理、工作区重置或会先删除输出目录的操作前，必须将目标规范化为绝对路径并解析现有祖先中的符号链接；递归下降和每一次破坏性系统调用都必须逐级绑定已核验目录身份，即时复核 inode、device 和链接状态，并使用不跟随链接且原子拒绝替换的系统能力，工具无法保证时禁止执行。
- 目标是 home、工作区或仓库根、用户数据集合根、这些目录的祖先，跨挂载点、链接到隔离目录外的对象，或无法证明为本任务新建且无外部硬链接的隔离目录时，禁止执行破坏性操作；这些边界证明无法保持到对应系统调用执行时也必须禁止。
- 验证删除或覆盖保护时，只能使用本任务从当前源码状态重新构建的产物，并记录源码状态、构建命令和产物哈希后在执行前再次核验；禁止使用真实用户目录、旧构建或跳过构建的产物验证。
- 恢复数据时的复制、移动和重命名必须使用原子不覆盖语义；多步操作任一步失败或目标、父目录身份发生变化时，立即停止并保留失败瞬间的全部现场状态和路径，禁止自动清理、回滚或继续下一步。

## 项目与同步边界

- 规则归属、项目规则位置和同步分层遵循项目治理规则；本文件只补充敏感信息、私有配置和上传前检查边界。
- 用户已将公司项目纳入当前执行任务后，读取完成任务所需的项目规则视为已确认；复制、修改或上传仍需明确授权。
- 公司项目、私有仓库、内部环境和敏感配置的边界以当前执行任务为准；范围内无副作用取证直接执行，凭据读取或任何有副作用、副作用不明、边界不明的操作仍需确认。
- 用户说“这件事跟公司项目无关”或“不要改某项目”后，该限制立即作为硬约束；后续除非用户明确解除，否则不能触碰该项目文件。
- 测试输出、接口响应、临时预览页、截图和诊断缓存属于会话临时产物，默认只能放在本机临时目录或明确的私有工作区；不要放进项目仓库、提交范围或公开同步目录。
- 上传公开仓库前必须做敏感扫描，至少检查 token、password、cookie、内网 IP、公司域名和个人绝对路径。
