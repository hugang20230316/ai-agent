# Agent 长任务执行规则

- 长耗时、批量请求、批量验证、批量构建、批量测试、批量文件处理、批量数据查询和多工具串联任务，必须先拆成可观察、可中断、可恢复的小批次；不得一次性启动多个不可独立观察、不可独立失败记录或不可单独补跑的请求或命令后统一静默等待。
- 单个长耗时请求、命令或子任务必须设置工具支持的明确超时；工具不支持显式超时时，必须设置单次观察等待上限。
- 预期应退出的后台命令返回运行会话后，必须立即开始有界轮询；等待、关闭或回收子 agent、reviewer、后台命令、浏览器会话和服务进程时，必须设置单次观察等待上限并按沟通规则反馈进度。同一对象达到既定观察上限仍无结果，或用户明确指出本轮 agent 执行长时间没有可见进展时，立即停止当前长链并切回主线程，以可独立观察的最小短步骤复核；复核恢复前不得启动依赖步骤或可替代的委派、审查和长等待链，用户目标不可替代的主验证仍可在有界复核后继续。
- 本规则中的同一对象指同一个运行实例、会话、子 agent、reviewer、浏览器会话或服务进程；不指同一条命令文本。重新启动新的本地命令进程时，仍必须重新设置显式超时。
- 若关闭、回收、恢复或清理工具不支持显式超时，不得把该动作放入用户交付的关键路径；记录未清理状态和未覆盖风险后，继续执行本地复核或最终收口。
- 同一批次中，互相依赖、耗时不确定或输出不可独立观察的子任务默认串行；确需并发时，必须限定并发上限，并保证每个子任务有独立输出、独立失败记录和可单独补跑条件。
- 每完成一个子任务，必须保存关键结果或进度证据；中断、压缩、重启或恢复后，先读取已有结果，只补跑缺失或失败项，不重复执行已成功项。
- 长任务执行期间必须按阶段反馈进度，说明当前对象、已完成数量、失败数量、下一步和是否仍在验证；不得把阶段性进展包装成最终完成。
- 连续出现超时、无响应、服务重启、依赖不可达或结果文件缺失时，立即停止扩大批量，改用最小单元复核根因；没有复核证据前不得继续追加同类批量请求。
- 窄范围修复连续叠加新分支、补丁明显超出原问题边界，或出现修一处复现另一处时，立即冻结新增策略，回到单一已证实的失败类别和最小补丁；大型重构或全面重写只有在用户明确要求时才允许继续扩大范围。
- 最终收口必须说明执行分批方式、超时或等待上限、成功和失败数量、恢复依据、验证证据和未覆盖风险。
- 预期耗时超过 2 分钟的命令（例如大型项目完整构建、长时间测试套件），必须使用 `run_in_background: true` 配合 Monitor 实时输出，或设置 ≥ 300000ms 超时；禁止用120s 默认超时执行长构建命令。
- dotnet 大型解决方案（.sln）构建耗时长且容易因 `--no-restore` 或输出过滤掩盖真实错误；优先只 build 直接修改过的单个 .csproj 项目文件，速度快且能精准捕获编译错误；需要全量验证时再构建完整 .sln，并使用 `-v minimal` 不加 grep 过滤。
